# 讨论区操作指南

## 定位

discuss 目录记录项目**思考进化过程**——不仅记录结论，更要记录：
- 为什么走这条路、放弃了哪条路
- 讨论中提出的质疑和反驳
- 方案如何一步步迭代变好的

目标是让后来者（或几个月后的自己）读文件时，能**理解当时的思考脉络**，而不是只看一个结论列表。

## 命名规范

```
YYYY-MM-DD_主题.md
```

示例：`2026-07-03_IPC管道通信设计.md`

## AI 指令

当用户说 **"把当前对话整理一下放到discuss目录下"** 或类似意思时，AI 执行以下流程：

1. **回顾对话**：从头梳理当前会话的完整脉络
2. **创建文件**：按命名规范在 `docs/discuss/YYYY-MM/` 下创建 `YYYY-MM-DD_主题.md`
3. **内容结构**（尽量按以下结构组织，但不强制逐条套用）：

   ### 讨论历程（核心章节）

   按时间顺序列出讨论中**提出的方案、质疑、反驳、转折**：

   ```markdown
   ## 讨论历程

   ### 回合 1：Xxx 方案
   - 提出人：xxx
   - 要点：...
   - 被反驳/接受的理由：...

   ### 回合 2：改为 Yyy 方案
   - 转折点：xxx 提出了什么问题
   - 新方案：...
   ...
   ```

   每个重要转折都要**记录是谁、因为什么**触发的。

   ### 最终结论

   总结性的决策汇总：

   ```markdown
   ## 最终结论

   | 决策项 | 结论 | 理由 |
   |--------|------|------|
   | ... | ... | ... |
   ```

   ### 遗留问题（可选）

   讨论中识别出但本次未解决的问题，指向 `docs/architecture/99-tbd.md` 对应章节。

   ### 产出物

   本次讨论创建/修改的文件列表。

4. **告知用户**：文件已创建，路径是什么
